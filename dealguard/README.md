# Deal Guard

Deal Guard is a discreet listening copilot for conversations that matter — a
partner, a friend, a landlord, a client. You type what the conversation is
about and what you want from it; the phone listens and stays silent until the
other person speaks, then shows what they said and what you could say next,
timed to the end of their turn. For negotiations with hard numbers, the
advanced **deal dossier** mode adds deterministic red flags and fact cards
anchored to your own terms.

> Never concede what you already agreed.

Deal Guard is a real-time negotiation copilot for dealmakers (commercial real
estate, lending, M&A term sheets). Before a call you enter your deal's
ground-truth terms. During the call the app transcribes speech and a
deterministic gating engine shows at most one glanceable cue at a time on a
black "Glance HUD": a **RED FLAG** when a statement contradicts the record or
crosses a walk-away boundary, a **FACT CARD** when someone asks about a known
term, otherwise nothing. After "End meeting" it produces a Deal Memorandum in
under a second.

This folder is a self-contained Capacitor 8 app (Vite 8 + React 18 +
TypeScript + Tailwind 3) targeting iOS and Android. It shares nothing with the
rest of the repository.

- Bundle / application id: `com.shlomo.dealguard`
- Version: 1.0.0 (build 1)
- Support: support@dealguard.app · https://dealguard.app

## Quick start

Requirements: Node 22, JDK 21 (Android), Xcode 16+ with CocoaPods (iOS).

```bash
cd dealguard
npm install
npm run dev              # web preview at http://localhost:5173
npm test                 # Vitest unit tests
npm run e2e              # Playwright E2E (Chromium)
npm run e2e:screenshots  # writes store screenshots (see below)
npm run check            # typecheck + test + build

npm run cap:sync         # build web bundle and sync into android/ and ios/
npm run cap:android      # ... then open Android Studio
npm run cap:ios          # ... then open Xcode (ios/App/App.xcodeproj, scheme App — SPM, no CocoaPods)
```

Native builds outside the IDE:

```bash
cd android && ./gradlew assembleDebug        # or bundleRelease
cd ios/App && xcodebuild -project App.xcodeproj -scheme App -sdk iphonesimulator build
```

Optional environment variables (read at build time):

| Variable | Purpose |
|---|---|
| `VITE_RC_IOS_KEY` | RevenueCat public SDK key for iOS. Empty disables purchasing. |
| `VITE_RC_ANDROID_KEY` | RevenueCat public SDK key for Android. Empty disables purchasing. |

Deepgram, Gemini and Groq keys are never built in; the user enters them in
Settings and they are stored on-device only.

## The three listening modes

| Mode | Input | Network | Keys needed |
|---|---|---|---|
| **Demo** | Built-in scripted negotiation ("Harbor Point Industrial (Sample)") | None | None |
| **Live (Deepgram)** | Phone microphone → 16 kHz PCM → Deepgram nova-3 streaming with diarization | Deepgram only | User's Deepgram key |
| **Companion** | Phone is a Glance HUD for a desktop daemon over LAN | `ws://<lan-ip>:8765/hud` | None |

Demo mode is what store reviewers should use; it requests no permissions.
Run `npm run mock-hud` on a laptop to exercise Companion mode locally (see
`docs/COMPANION_PROTOCOL.md`).

## Zero persistence

Audio exists only in RAM. The raw transcript is discarded when the memorandum
is built. Only structured deal terms, the ledger, session memoranda and
settings are stored, on-device, via Capacitor Preferences; API keys go to the iOS Keychain / Android Keystore. There are no
accounts, no analytics SDK, no ads and no server of ours. Settings offers
"Export my data" and "Delete all data".

## Renaming the brand

Everything user-visible reads from `src/brand.ts` (name, tagline, bundle id,
URLs, support email, version). Change it there, then:

1. Update `appId` / `appName` in `capacitor.config.ts` and re-run `npm run cap:sync`.
2. Update `fastlane/metadata/**` and `fastlane/Appfile`.
3. Update the bundle id in Xcode and `applicationId` in `android/app/build.gradle`.
4. Re-create the RevenueCat apps and store products if the id changed.
